# PivotIQ Result Page Redesign Brief

## Executive Summary

The current result page already contains strong thinking and useful report content, but it does not yet feel like one premium decision document. It feels like multiple strong modules competing for attention at the same time.

The biggest issue is not aesthetics alone. It is hierarchy failure:

- too many sections are visually promoted at once
- too many gradients and tinted panels imply equal importance
- too many chips, badges, micro-callouts, and metric cards fragment the reading flow
- the page explains the recommendation in several overlapping ways before the user reaches the tabbed detail
- the stay-and-advance tab contains good content but still reads like several adjacent feature cards instead of one operating narrative

The redesign should move the page toward a calmer editorial briefing:

- one dominant recommendation
- one clear reason it wins now
- one immediate operating move
- one proof asset to build
- one backup path kept visible but secondary

This should feel like a trusted strategic memo with product polish, not an AI dashboard.

## What Is Visually Wrong Now

### 1. Too many “hero” moments

The page currently stacks several top-of-page sections that all behave like primary summaries:

- report hero
- recommendation why card
- executive summary
- recommendation stack
- decision clarity / ROI / first 30 days block
- interpretation block
- paid value summary / strategic read block

This creates visual inflation. The user gets many answers before they know which one is the real answer.

### 2. Over-accented surfaces

The current design uses:

- orange
- teal
- navy
- cream
- multiple tinted backgrounds
- multiple radial or linear gradients
- bright chips and badge fills

Individually these are fine. Together they create noise and lower perceived seriousness.

### 3. Card over-fragmentation

Many sections break one idea into too many sub-cards. The result page often reads as:

- heading
- mini card
- mini card
- mini card
- supporting card
- callout card

instead of a single coherent section with one scan pattern.

### 4. Inconsistent importance

Some less important details are louder than core decisions. A user should immediately understand:

- what the recommendation is
- why it wins
- what to do first
- what proof to build
- what backup path exists

Right now, multiple status pills, stat cards, and wrapper treatments compete with those essentials.

### 5. Stay tab still feels modular, not narrative

The stay-and-advance work improved the content significantly, but the presentation still spreads the story across too many separately highlighted surfaces:

- stay summary hero
- decision matrix
- market reality check
- operating narrative
- proof readiness
- skill-gap summary
- proof builder
- promotion pack
- learning path
- full skill cards

The content is strong. The rhythm is not yet disciplined enough.

## Design Principles

### 1. One answer first

The page should state the recommendation once, clearly, with calm authority.

### 2. Editorial over dashboard

Prefer:

- strong typography
- cleaner section framing
- restrained stat usage
- fewer but better surfaces

Avoid:

- dense widgets
- decorative KPI clutter
- colorful module collections

### 3. Emphasis is scarce

Only a few things deserve strong accent treatment:

- the primary recommendation
- the immediate next move
- the proof asset
- the active tab state

Everything else should sit on a quieter neutral system.

### 4. One section, one job

Each section should answer a specific question:

- recommendation: what should I do?
- decision stack: why this, and what is the backup?
- stay section: how do I become harder to replace in my current lane?
- pivots section: what are the alternate moves?
- plan section: how do I execute week by week?

### 5. Calm premium mobile experience

On mobile, the current card density becomes especially noisy. The redesign should improve:

- vertical rhythm
- line length
- spacing between section ideas
- reduction of stacked mini-panels
- fewer inline pills and decorative blocks

## Proposed Visual System

### Palette

Base the page on a restrained neutral palette:

- warm ivory page background
- white primary surfaces
- soft stone secondary surfaces
- charcoal or deep navy text

Use accents sparingly:

- one restrained amber for decision emphasis and directional priority
- one muted green-teal for stay / defensibility / operating leverage

Rules:

- no rainbow page effect
- no more than one accented surface per section unless a comparison truly requires it
- gradients only when they create focus, never as decoration

### Hierarchy Rules

- H1 / primary editorial headings should carry the authority, not badges
- labels should be small and quiet
- badges should communicate state, not decorate
- supporting metrics should be compact and secondary

### Card Rules

Use only three surface patterns:

1. Primary briefing surface
   - white or near-white background
   - subtle border
   - modest shadow
   - used for key recommendation areas

2. Secondary support surface
   - quiet neutral fill
   - subtle border
   - no heavy gradient
   - used for detail groupings and supporting evidence

3. Accent support surface
   - very light tinted background
   - only for the most important highlight within a section
   - one per section where possible

### Accent Rules

- primary recommendation can carry accent emphasis
- first action / proof / key stay move can carry mild emphasis
- avoid tinting every child card inside an already tinted parent

### Badge Rules

- remove decorative badges that do not change decisions
- reduce uppercase pill count
- confidence labels should be quieter and more integrated

### Spacing Rhythm

- more top-level whitespace between major sections
- tighter internal spacing inside support cards
- fewer nested wrappers

### Section Transition Rules

The page should read in this order:

1. Situation and recommendation
2. Why it wins now
3. Immediate operating move and proof
4. Detail by lens: breakdown, stay, pivots, plan

### Mobile Layout Rules

- fewer 3-4 column mini-grids near the top
- convert dense stat clusters into stacked rows or simpler 2-up groupings
- reduce chip walls
- keep key action, proof, and backup path above dense detail

## Section-by-Section Redesign Plan

### 1. Hero

Keep:

- risk framing
- role / industry / generated date
- report-level narrative

Change:

- soften decorative background
- reduce visual glow and saturation
- simplify stat cards
- remove or demote extra highlight treatments inside hero

### 2. Executive Summary

Target role:

- become the single dominant briefing block after the hero

Change:

- one strong editorial headline
- one short confidence-setting paragraph
- one clean summary grid for:
  - why this wins
  - first move
  - proof to build
  - what changes in 30 days

Avoid:

- oversized tinting
- too many separate feature boxes

### 3. Recommendation Stack

Target role:

- show primary recommendation, safer backup, and stay path clearly

Change:

- simplify into a cleaner comparison structure
- reduce repeated support boxes per path
- keep only the most useful details:
  - path label
  - why it exists
  - next move
  - proof

Avoid:

- too many nested mini-panels
- loud reason pills

### 4. Pre-tab Summary Cluster

Current problem:

- too many overlapping summary cards before tabs

Change:

- remove or fold duplicate summary sections into a single strategic-briefing block
- keep only the highest-value top-level synthesis before tabs

### 5. Stay-and-Advance Tab

Target role:

- read like one operating narrative, not a collection of AI feature modules

Restructure around:

1. pressure and human edge
2. workflow to redesign
3. AI boundary and business result
4. proof and manager conversation
5. learning only where it strengthens the workflow

Specific simplifications:

- keep the stay hero quieter
- preserve the decision matrix, but reduce contrast noise
- merge or visually align safety, workflow, proof, and promotion content around one consistent shell language
- demote repetitive support cards
- keep full skill cards lower and less visually dominant

### 6. Pivot Paths Tab

Change:

- keep comparison useful but quieter
- reduce loud card states and colorful chips
- make alternate pivots clearly secondary to the main recommendation

### 7. Plan Tab

Change:

- keep progress and weekly execution tools
- soften decorative tinting
- make roadmap feel operational rather than gamified
- keep progress panels clearer and flatter

## What Should Be Simplified or Removed

- duplicate top-level strategic summary blocks
- overly prominent recommendation-why surface inside the hero
- repeated tinted child cards inside tinted parent cards
- decorative chip clusters where plain text lists are clearer
- loud status treatments that do not change user decisions
- unnecessary gradient backdrops on support sections

## Files Likely Affected

- `lib/report-data.js`

## Ordered Implementation Plan

1. Establish the calmer visual system
   - soften page background
   - reduce card shadow intensity
   - normalize tab and chip styling
   - define quieter accent usage

2. Rebuild the top report flow
   - simplify hero
   - strengthen executive summary
   - simplify recommendation stack
   - remove duplicate pre-tab summaries

3. Rework the stay tab around one operating narrative
   - unify key surfaces
   - reduce module competition
   - keep proof and manager guidance prominent
   - demote repetitive learning and skill surfaces

4. Quiet the pivot and plan tabs
   - keep usefulness high
   - reduce colorful dashboard feel
   - normalize section wrappers and stat blocks

5. Verify
   - report-quality tests
   - recommendation tests
   - production build
